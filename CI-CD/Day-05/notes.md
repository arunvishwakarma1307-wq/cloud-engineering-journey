# Day-05 — GitHub Actions Job Outputs & Data Passing Between Jobs

## 1. Job Outputs

In GitHub Actions, Job Outputs are used to pass a value generated in one job to another job.

Example flow:

Build Job → Generate Value → Job Output → Test Job

This allows data to be shared between different jobs in a workflow.

---

## 2. Step ID

A step can be given an `id` so that its output can be referenced later.

Example:

`id: generate-value`

The step ID is used when accessing the output generated by that step.

---

## 3. GITHUB_OUTPUT

`GITHUB_OUTPUT` is used to create an output value from a GitHub Actions step.

It allows a step to expose a value as an output.

In Day-05, the `BUILD_VERSION` value was generated and written as a step output.

---

## 4. Job Output

A step output can be exposed as a Job Output.

The purpose of a Job Output is to make a value available to another dependent job.

In Day-05:

Build Job → `BUILD_VERSION` generated → Job Output created.

---

## 5. needs

`needs` is used to define a dependency between jobs.

If the `test` job must run after the `build` job, the `test` job can use:

`needs: build`

This means that the `test` job depends on the `build` job.

---

## 6. needs.<job>.outputs.<output>

A dependent job can access an output from another job using the `needs` context.

General structure:

`needs.<job-name>.outputs.<output-name>`

In Day-05, the `test` job received the output generated by the `build` job.

---

## 7. Data Passing Between Jobs

Different GitHub Actions jobs normally run in separate environments.

Therefore, a value generated in one job needs an appropriate method to be passed to another job.

Job Outputs provide a way to pass simple values between dependent jobs.

Day-05 flow:

Build Job
↓
Generate Value
↓
Step Output
↓
Job Output
↓
Test Job
↓
Receive Output

---

## 8. Step Output vs Job Output

### Step Output

A Step Output provides a value from a particular step.

The step needs an `id` so that its output can be referenced.

### Job Output

A Job Output exposes a value at the job level.

A dependent job can then access that value.

Simple difference:

Step Output → Value from a specific step

Job Output → Value available to another dependent job

---

## 9. Job Dependency and Data Passing

`needs` is mainly used to define the dependency between jobs.

Job Outputs are used to make a value from one job available to another job.

Example concept:

`build` job completes
↓
`test` job starts
↓
`test` job receives the build output

Therefore, Day-05 covered both job dependency and data passing.

---

## 10. Day-05 Practical Concept

In Day-05, the build job generated the following build version:

`day-05-build-001`

This value was exposed as a Job Output.

The dependent test job then received the same value.

The test job displayed:

`Received build version: day-05-build-001`

This confirmed that the value was successfully passed from the build job to the test job.

---

## 11. Why Job Outputs Are Useful

Job Outputs are useful when a value generated or calculated in one job needs to be used by a later job.

Examples:

- Build version
- Environment name
- Generated identifier
- Release information
- Status information
- Deployment-related values

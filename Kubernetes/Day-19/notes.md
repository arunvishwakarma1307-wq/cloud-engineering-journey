# Day 19 - Helm Release Management

## What is a Helm Release?

A Helm Release is an instance of a Helm Chart running in a Kubernetes cluster. Every time a Helm Chart is installed, Helm creates a Release and tracks its lifecycle.

Example:

my-nginx

---

## Helm Status

The `helm status` command displays detailed information about a Helm Release.

It shows:

- Release Name
- Namespace
- Status
- Revision
- Last Deployment Time
- Resources
- Notes

---

## Helm Values

Helm Charts use configuration values stored in a `values.yaml` file.

The command:

helm get values <release-name>

displays the user-supplied configuration values used during installation.

---

## Helm Manifest

Helm converts Chart templates into Kubernetes YAML files before deploying them.

The generated YAML files are called the Manifest.

The command:

helm get manifest <release-name>

displays the complete Kubernetes manifest generated by the Helm Chart.

---

## Helm Upgrade

The `helm upgrade` command updates an existing Helm Release without reinstalling the application.

Every successful upgrade creates a new Revision.

---

## Helm Revision

A Revision is a version history of a Helm Release.

Example:

Revision 1 → Initial Installation

Revision 2 → Upgrade

Revision 3 → Rollback

Helm stores every revision, making it easy to restore previous versions.

---

## Helm History

The `helm history` command displays all revisions of a Helm Release.

It helps users:

- View previous versions
- Track upgrades
- Identify rollback points

---

## Helm Rollback

Rollback restores a previous working Revision.

Instead of replacing the old Revision, Helm creates a new Revision that contains the previous configuration.

---

## Helm Uninstall

The `helm uninstall` command removes a Helm Release and deletes all Kubernetes resources created by that Release.
